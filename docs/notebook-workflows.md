# Notebook workflows

- Relationship properties can be imported/exported in CSV/TSV using `connection_attribute:<name>` columns, captured from SQL aliases with the same prefix, and exchanged through GraphML `attributes_json` or ordinary edge data keys. They are searchable and shown on the selected-link inspector; SQL-owned properties remain source-managed. SQL Review’s **Relationship properties** filter isolates captures where those values changed. The **Entity properties** filter separately shows changes to SQL supplied source and target attributes. KML line placemarks include relationship properties in ExtendedData.

- The main workspace bar opens **Chart**, **Timeline**, **Connections**, **SQL Review**, **Automation**, **Entities**, and **Sources** directly. Keyboard shortcuts are Ctrl/Command+1 for Chart, +2 for Timeline, +3 for Connections, +4 for SQL Review, +5 for Automation, +6 for Entities, and +7 for Sources. The Data page’s **Case Records** row remains available for switching among record views while working in that page.

- The **Charts** row keeps multiple named charts in one case. Choose a tab to switch graphs, right-click a tab to rename or delete it (the last chart cannot be deleted), **＋ New chart** to start a blank chart, or select an entity or relationship and use **Copy selection to new chart** to branch that selection into a separate graph. Each chart keeps its own zoom and pan when you switch tabs and after the case is reopened. Deletion asks for confirmation and switches to another chart when the active one is removed. Chart graphs remain isolated; SQL snapshots and automation jobs stay with the case and are available while any chart is open.

- CSV/TSV, GraphML, and KML import/export actions operate on the active chart tab. Exports carry its chart title; GraphML and KML also retain the case title as separate metadata. Importing a named exchange file or CSV/TSV into an empty, automatically named chart adopts the source chart title; importing into a populated or manually named chart keeps the destination title. SQL capture history, automation jobs, and run history remain case-wide; ingesting a snapshot updates the active chart only.

- Open **Sources** from the main workspace bar (or Ctrl/Command+7) to see entity and connection records attributed to each imported source, including SQL, CSV/TSV, and GraphML provenance. Search all terms across source keys, database paths, and series names to find a source in a larger case. **Highlight on chart** clears the selected item and temporary path, group, and timeline filters, then fits and highlights that source’s entities and links; **View entities** and **View connections** open source-filtered records. SQL sources offer **Review SQL** to jump directly to their snapshot comparisons. **Open SQL job** loads the exact originating job for automated captures; for manual captures without a run record, it appears only when one saved job uniquely matches the database and series. SQL Review provides the same direct action beside the selected capture, so analysts can move from a saved result into its automation job without returning to Sources. If the job’s current query or parameters differ from the selected capture, SQL Review shows a configuration-difference warning before opening the job. Imported GraphML SQL capture catalogs appear in a separate expandable history with database, series, capture IDs, times, counts, and skipped rows; the view labels them as exchange metadata because GraphML does not include the local snapshots needed to compare or replay captures. Entity identities and link provenance stay local to the case.
- Build and edit entity/link charts. Use **＋ Entity** to search common and case-specific types or enter a custom entity type. Use **＋ Link** to search common and case-specific relationship types or enter a custom type, then choose both endpoints. Inspect attributes and source references, arrange with connectivity, breadth-first hierarchy, or alphabetical grid layouts while pinning selected entity positions, and review timelines with ISO dates positioned by elapsed time. Drag unlocked entities to reposition them; a locked entity remains fixed when dragged and reports that it must be unlocked in Data first. Drag across a fully dated timeline axis to apply a chart time filter; records outside the interval are dimmed. Use **Clear range** or close Timeline to remove the temporary filter without changing case data. Mixed or invalid dates retain approximate event ordering and disable range filtering; the timeline reports the number of links lacking valid ISO dates. When a chart date range is active, **Restrict path to active timeline range** includes only dated links inside that range by default; turn it off to use the range as a display filter only. Changing or clearing an applied range invalidates the current path result. Use **Follow link directions** in shortest-path analysis to require travel along directed links; undirected links remain traversable in either direction. Clear the option to treat directed links as traversable both ways. Search shortest-path endpoints by name, type, alias, attribute, or external source ID before choosing each endpoint. Name an investigation and choose **Save path** to keep its endpoint IDs and direction/time constraints in the case (a timeline constraint uses the active range when reopened); saved paths reject duplicate names. Open a saved path to restore its criteria and recompute the route against the current case, so deleted or changed relationships are not represented by stale link positions. Saved paths with missing endpoints are retained for repair and report the missing entity when opened; delete obsolete paths from the list. Use **Path JSON**, **Import path**, and **Export JSON** in the path panel to exchange packages in the desktop app, or use `--export-path` and `--import-path` from scripts; the package contains endpoint IDs plus names and types, and import falls back to a unique name/type match when IDs differ. Ambiguous or missing endpoints are rejected, and `--name` can adapt the imported bookmark name. **Time flow** can keep link dates nondecreasing or nonincreasing along a path; it requires valid ISO dates on every traversed connection, and same-day links are allowed. Use **Any date order** when chronology is irrelevant. Expand **Connection records for path steps** to inspect the exact traversed record marked **PATH RECORD** alongside parallel alternatives, compare dates, confidence, evidence, notes, and source, then select any record to focus it on the chart. **Show path on chart** highlights the exact traversed records, including a directed record when the route follows it against its arrow because direction-following is off. Graph edits and changes to a link’s date or direction clear the path result so its supporting records cannot become stale. Use **Fit all** to frame every entity after manual rearrangement; path analysis can fit the full shortest path separately. The chart navigator shows the full network and current viewport; click a region in its overview to jump there. Parallel relationship records render on separate chart lanes and can be selected individually.
- Use the chart sidebar’s **Search chart items…** field to search all items, entities only, or relationships only. Entity searches match any word in the name, type, detail, aliases, source external IDs, custom attributes, or preserved merged-record properties. Multiword searches require every term to match the item, even when terms appear in different fields. Results rank entity-name or relationship-label/endpoint matches first; choosing a result focuses it on the chart and clears active source, group, path, and timeline filters that could dim or hide it.
- The chart sidebar also searches relationship records by connection ID, relationship type, date, confidence, evidence, analyst/source notes, provenance, endpoint names, and endpoint properties. Matching links appear under **Matching relationships**, with relationship labels and endpoint matches ranked ahead of supporting-property matches; select one to focus that exact record and use **View on chart** when working from Data. Both handoffs center the selected record and clear active chart-only source, group, path, and timeline filters so they do not hide the destination.
- Save up to ten named selection sets from the chart’s **Analysis** sidebar to return to important entities or groups later. Showing a set focuses those entities on the chart; entities deleted from the case are omitted when the set is recalled.
- From a selected SQL-backed relationship, use **Review SQL series** to compare its captures or **Open SQL job** to load the exact originating automation job. Manual captures offer the job action only when one saved job uniquely matches their database and series.
- Entity and connection tables use the same all-terms property search as the chart sidebar, including entity external IDs and merged-record properties and connection endpoint properties. Source and selected-entity filters continue to narrow the matching rows.
- In **Connection records for path steps**, each parallel record is labeled as the traversed **PATH RECORD**, an **ELIGIBLE ALTERNATE**, or **EXCLUDED** by the active direction, timeline-range, or time-flow criteria. Excluded records remain available as evidence and show why they could not support the analyzed route.
- Find weakly connected NETWORK GROUPS from the Analysis sidebar, treating directed links as undirected for discovery. Show a group to fit it on the chart and highlight its entities and internal links. **NETWORK BRIDGES** finds articulation entities whose removal would split their connected group, ranks them by resulting fragments, and exposes all links touching each bridge with direction, date, confidence, record ID, evidence reference, and source notes. Select a record to focus it on the chart; show the bridge neighborhood or use it as a shortest-path endpoint. **Use as path start/end** places the bridge into the shortest-path controls to continue tracing the network.
- Save up to ten named **Selection Sets** from the current chart focus in the Analysis sidebar. Use **Show** to fit and highlight the saved entities later; recalling a set clears temporary path and timeline filters, and deleted entities are skipped. Selection sets are stored in the case file and can be deleted from the list.
- Review the grouped Connections table by entity pair and relationship type, then expand a pair to inspect its link records. The selected-entity inspector groups linked entities and their records; focus a counterpart or an individual dated/directed record on the chart. The selected-link inspector identifies its SQL series and database and opens that series directly in snapshot comparison review. Entity connection counts remain distinct counterpart entities; the chart’s MOST CONNECTED ranking can compare distinct entities, all link records, directed incoming links, or directed outgoing links and filter each measure by relationship type. Highlight top 10 to fit those entities on the chart and emphasize their incident links. Parallel link records count separately in the link-based measures, and undirected links are excluded from incoming/outgoing rankings. Switch to the Link records table for a sortable row view by record ID, source, relationship, target, date, confidence, or source reference. Filter across endpoints, evidence, notes and ingest provenance; scope results to all connections or those involving the selected entity, then return a selected link to the chart.
- Search and sort entity records; selecting a result from the chart sidebar centers it on the canvas. Focus chart entities from the most-connected list and fit the full shortest path into the chart view.
- Review likely duplicate entities of compatible types before merging. Candidate rows show whether the match came from similar names or a shared source ID; different IDs from the same source are excluded. Merge rewires links and preserves aliases, source IDs, attributes, notes, and the original record in entity history. Saved paths and selection sets that reference the removed entity are remapped to the retained entity; the active computed path is cleared because its link route may have changed.
- Reusing an import design against a changed header set preserves still-matching column names, but missing mapped columns are called out by field and block import until corrected or cleared. This prevents optional identifiers and provenance fields from silently disappearing during schema adaptation.
- The import wizard opens **Preview mapped output** by default and shows each sample row’s resulting entity or link, endpoints, relationship, source IDs, connection ID, date, and filter status after trimming and value transforms. Mapped merge-history counts are shown; malformed JSON and conflicts among sampled rows are flagged before import. Full-file staging checks all repeated entity histories and rejects conflicts before changing the case. Review this projection before importing to catch swapped or misidentified columns.
- CSV/TSV import inspects the full file on a background worker, reports rows scanned and the total data-row count, and displays the first four records in the mapping preview without blocking the chart UI. Cancel a long inspection from the toolbar; scanning stops between records.
- Import/export relationship CSV or TSV (`.tsv` and `.tab` paths use tab delimiters) with optional `connection_id`, `ingest_source`, and entity properties retained across round-trips. Exports include `source_entity_id` and `target_entity_id` UUID columns so reimport preserves chart identity even when names are duplicated, plus `source_external_ids_json` and `target_external_ids_json` for source-system identities used by SQL ingestion, and `source_merged_records_json`/`target_merged_records_json` to preserve merged entity records across CSV/TSV and GraphML round-trips. **Import CSV/TSV** opens a design dialog with a row preview that shows transformed values, whether each sample passes the active row filters, flags incomplete filters or transforms, and disables Import until endpoint mappings, filters, transforms, and relationship-property mappings are valid. Its field mapping covers source/target, entity IDs, types, relationship, date, confidence, direction, identifiers, notes, provenance, endpoint details, aliases, colors, chart positions, position locks, and custom entity attributes. Relationship-property mappings let analysts map arbitrary source columns to named link properties; columns named `connection_attribute:<key>` are still detected automatically. The row preview shows each mapped link-property name and transformed value, and flags incomplete or duplicate property mappings before import. Duplicate headers, ignoring case and surrounding whitespace, are rejected so a mapping cannot silently choose the wrong column. Save all-match row filters (equals, contains, is empty, or is not empty), optional whitespace trimming, and per-column value transforms with each design; transforms can replace substrings, map exact values, or normalize case, run in saved list order before row filters, and appear in the import preview with the original value available on hover. Exact-value mappings standardize categories without altering partial matches in identifiers. Skipped rows are reported. Save named import designs in the case file; a unique design saved for the same set of column names is applied automatically, while multiple matches remain available for manual selection. Header order, case, and surrounding whitespace do not affect the match; standard headers are detected automatically. Rows marked `record_type=entity` carry isolated entities; connection rows leave `record_type` blank or use `connection`. The `notes` column carries analyst notes; `source_notes` carries notes supplied by SQL or another source. If a matching row is reimported without a `source_notes` column, its saved source notes are preserved; a present but blank `source_notes` cell clears them. Endpoint detail, aliases, chart color, and normalized chart position use `source_detail_json`/`target_detail_json`, `source_aliases_json`/`target_aliases_json`, `source_color`/`target_color` (`#RRGGBB`), and `source_x`/`source_y`/`target_x`/`target_y` (0–1), and `source_position_locked`/`target_position_locked` (true/false); JSON `""` clears detail and `[]` clears aliases. Empty attribute, color, and position cells leave existing values unchanged. Reimporting an ID-bearing row updates the matching record within the same ingest source; provenance-bearing rows without IDs update only a unique natural-key match. When that source belongs to a saved SQL snapshot, imported rows must match the snapshot-owned records exactly, while analyst-note changes remain allowed; changed or new SQL-owned facts must be ingested from SQLite so the chart cannot diverge from its immutable snapshot. Rows without IDs or provenance append because they cannot be matched safely. CSV/TSV export also refuses a relationship with a missing endpoint entity instead of silently omitting that row. Missing confidence defaults to 2; supplied confidence must be 1–3. Direction accepts true/false, 1/0, yes/no, directed/undirected, or →/↔; invalid supplied values reject the staged import. Use `source_attribute:<key>` and `target_attribute:<key>` columns for entity attributes; non-empty imported values update matching attributes. Repeated rows must agree on non-empty values for the same entity property or the staged import is rejected. Sparse external-identity lists are unioned across repeated rows by source namespace; two different IDs from the same namespace for one chart entity reject the staged import. Save/open local JSON case files; SQL snapshot history is retained with the case. The default case is restored at launch when it exists. Opening another case or creating a new case prompts before discarding unsaved edits. **Save case** writes to the active case file; use **Save as** to choose a different path, or edit the staged **Case file** path and use **Open case** to load it. Keyboard shortcuts: Ctrl/Command+1 for Chart, +2 for Timeline, +3 for Connections, +4 for SQL Review, +5 for Automation, +6 for Entities, and +7 for Sources; Ctrl/Command+S saves, Ctrl/Command+Shift+S saves as, Delete removes the selected chart item when a text field is not active, and Escape clears selection or dismisses the unsaved-changes prompt.
- For map exchange, populate coordinate entity attributes through CSV/TSV mappings or SQL result aliases such as `source_attribute:latitude`, `source_attribute:longitude`, `target_attribute:latitude`, and `target_attribute:longitude`; isolated CSV entity rows can use the source attribute mappings as well. The chart toolbar or Data path controls export KML 2.2 point placemarks for entities with valid WGS84 coordinates and line placemarks for links whose two endpoints are mapped. The export includes entity attributes, external IDs, aliases, merged-record history, chart color and placement, and link metadata; these ExtendedData fields survive reimport. Unmapped entities are skipped and the CLI reports links without both coordinates. **Import KML** accepts Point and LineString placemarks, stages them through the standard entity reconciliation flow, and can be run from the toolbar or as `arch-notebook --import-kml case.json locations.kml --json`. It reads ExtendedData for attributes and record metadata; line endpoints resolve by exported entity IDs or unique point coordinates. An explicit but unknown endpoint ID fails instead of falling back to a coordinate match. Unsupported geometries and ambiguous endpoint matches stop the import before the case is saved.

All bundled case examples are fictional. Arch Notebook does not connect to a service or transmit case data.
