# Notebook workflows

- Open **Data → Sources** to see the entity and connection records attributed to each imported source, including SQL, CSV/TSV, and GraphML provenance. **Highlight on chart** focuses and highlights that source’s entities and links; **View entities** and **View connections** open source-filtered records. SQL sources offer **Review SQL** to jump directly to their snapshot comparisons, and sources with a matching saved database/series job also offer **Open SQL job**, which loads that job into the automation editor for validation or adaptation. Entity identities and link provenance stay local to the case.
- Build and edit entity/link charts, choose both endpoints when creating a link, inspect attributes and source references, arrange with connectivity, breadth-first hierarchy, or alphabetical grid layouts while pinning selected entity positions, and review timelines with ISO dates positioned by elapsed time. Use **Fit all** to frame every entity after manual rearrangement; path analysis can fit the full shortest path separately. The chart navigator shows the full network and current viewport; click a region in its overview to jump there. Parallel relationship records render on separate chart lanes and can be selected individually.
- Find weakly connected NETWORK GROUPS from the Analysis sidebar, treating directed links as undirected for discovery. Show a group to fit it on the chart and highlight its entities and internal links.
- Review the grouped Connections table by entity pair and relationship type, then expand a pair to inspect its link records. The selected-entity inspector groups linked entities and their records; focus a counterpart or an individual dated/directed record on the chart. The selected-link inspector identifies its SQL series and database and opens that series directly in snapshot comparison review. Entity connection counts remain distinct counterpart entities; the chart’s MOST CONNECTED ranking can compare distinct entities, all link records, directed incoming links, or directed outgoing links and filter each measure by relationship type. Highlight top 10 to fit those entities on the chart and emphasize their incident links. Parallel link records count separately in the link-based measures, and undirected links are excluded from incoming/outgoing rankings. Switch to the Link records table for a sortable row view by record ID, source, relationship, target, date, confidence, or source reference. Filter across endpoints, evidence, notes and ingest provenance; scope results to all connections or those involving the selected entity, then return a selected link to the chart.
- Search and sort entity records; selecting a result from the chart sidebar centers it on the canvas. Focus chart entities from the most-connected list and fit the full shortest path into the chart view.
- Review likely duplicate entities of compatible types before merging. Merge rewires links and preserves aliases, attributes, notes, and the original record in entity history.
- CSV/TSV import inspects the full file on a background worker, reports rows scanned and the total data-row count, and displays the first four records in the mapping preview without blocking the chart UI. Cancel a long inspection from the toolbar; scanning stops between records.
- Import/export relationship CSV or TSV (`.tsv` and `.tab` paths use tab delimiters) with optional `connection_id`, `ingest_source`, and entity properties retained across round-trips. Exports include `source_entity_id` and `target_entity_id` UUID columns so reimport preserves chart identity even when names are duplicated, plus `source_external_ids_json` and `target_external_ids_json` for source-system identities used by SQL ingestion. **Import CSV/TSV** opens a design dialog with a row preview that shows transformed values, whether each sample passes the active row filters, flags incomplete filters or transforms, and disables Import until endpoint mappings, filters, and transforms are valid, plus field mapping for source/target, entity IDs, types, relationship, date, confidence, direction, identifiers, notes, provenance, endpoint details, aliases, colors, chart positions, position locks, and custom entity attributes. Duplicate headers, ignoring case and surrounding whitespace, are rejected so a mapping cannot silently choose the wrong column. Save all-match row filters (equals, contains, is empty, or is not empty), optional whitespace trimming, and per-column value transforms with each design; transforms can replace substrings, map exact values, or normalize case, run in saved list order before row filters, and appear in the import preview with the original value available on hover. Exact-value mappings standardize categories without altering partial matches in identifiers. Skipped rows are reported. Save named import designs in the case file; a unique design saved for the same set of column names is applied automatically, while multiple matches remain available for manual selection. Header order, case, and surrounding whitespace do not affect the match; standard headers are detected automatically. Rows marked `record_type=entity` carry isolated entities; connection rows leave `record_type` blank or use `connection`. The `notes` column carries analyst notes; `source_notes` carries notes supplied by SQL or another source. If a matching row is reimported without a `source_notes` column, its saved source notes are preserved; a present but blank `source_notes` cell clears them. Endpoint detail, aliases, chart color, and normalized chart position use `source_detail_json`/`target_detail_json`, `source_aliases_json`/`target_aliases_json`, `source_color`/`target_color` (`#RRGGBB`), and `source_x`/`source_y`/`target_x`/`target_y` (0–1), and `source_position_locked`/`target_position_locked` (true/false); JSON `""` clears detail and `[]` clears aliases. Empty attribute, color, and position cells leave existing values unchanged. Reimporting an ID-bearing row updates the matching record within the same ingest source; provenance-bearing rows without IDs update only a unique natural-key match. When that source belongs to a saved SQL snapshot, imported rows must match the snapshot-owned records exactly, while analyst-note changes remain allowed; changed or new SQL-owned facts must be ingested from SQLite so the chart cannot diverge from its immutable snapshot. Rows without IDs or provenance append because they cannot be matched safely. Missing confidence defaults to 2; supplied confidence must be 1–3. Direction accepts true/false, 1/0, yes/no, directed/undirected, or →/↔; invalid supplied values reject the staged import. Use `source_attribute:<key>` and `target_attribute:<key>` columns for entity attributes; non-empty imported values update matching attributes. Repeated rows must agree on non-empty values for the same entity property or the staged import is rejected. Sparse external-identity lists are unioned across repeated rows by source namespace; two different IDs from the same namespace for one chart entity reject the staged import. Save/open local JSON case files; SQL snapshot history is retained with the case. The default case is restored at launch when it exists. Opening another case or creating a new case prompts before discarding unsaved edits. **Save case** writes to the active case file; use **Save as** to choose a different path, or edit the staged **Case file** path and use **Open case** to load it. Keyboard shortcuts: Ctrl/Command+1, +2, and +3 switch to Chart, Timeline, and Data; Ctrl/Command+4 opens Automation directly and Ctrl/Command+5 opens SQL review directly; Ctrl/Command+S saves, Ctrl/Command+Shift+S saves as, Delete removes the selected chart item when a text field is not active, and Escape clears selection or dismisses the unsaved-changes prompt.

All bundled case examples are fictional. Arch Notebook does not connect to a service or transmit case data.
