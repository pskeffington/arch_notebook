# Analyst's Notebook compatibility map

Arch Notebook is a Rust desktop application inspired by IBM i2 Analyst's Notebook. This page tracks the product areas that shape its workflow and separates implemented behavior from compatibility gaps.

| Product area | Current Arch Notebook behavior | Remaining compatibility work |
| --- | --- | --- |
| Charting and feel | Dark desktop workspace, typed entities and connections, per-entity Icon, Theme line, Event frame, Box, Circle, or Text block representation, plus standalone chart labels and legends. Labels can be placed, edited, colored, resized, selected, dragged, copied, and deleted without affecting entity analysis. Legends populate from distinct entity types, relationship labels, and item attribute classes; attribute class circle, square, triangle, and diamond symbols can display values on matching entities and relationships. Entries can apply bounded nested/mixed AND/OR conditions (up to four group levels and eight leaves), as well as legacy flat conditions, to chart-item colors and optional matching-link widths without changing saved data. New expressions are optional and defaulted; pre-existing cases retain their prior rule behavior. Older application versions ignore the expression and show the retained legacy fields. Chart labels, legend styles, attribute display, and conditional color settings persist per chart and round trip through Arch Notebook GraphML metadata. Representations are persisted and exchanged through CSV/TSV, GraphML, and KML; ANX import/export maps supported chart items and preserves Arch Notebook labels/metadata when available, but has not been checked against IBM's XSD or application. | Confirm nested group semantics against IBM behavior before claiming parity; current official references establish ordered conditional rules, not nested mixed expressions. Expand conditional formatting to lookup tables, badges, size, visibility, type, and line styling. Add attribute data types, semantic types, and value formatting. Expand legend coverage to icon frames, fonts, time zones, layout/print positioning, and ANX import/round-trip semantics. Compare the interactive chart and editing flow against Analyst's Notebook in a running visual review; tune theme-line and event-frame behavior, palettes, symbols, canvas gestures, and property editing from direct observation. |
| Relationship multiplicity | Separate relationship records between the same entity pair are retained, drawn on parallel lanes, and individually selectable in Arch Notebook. This matches IBM's documented ability to import multiple links between a pair when chart multiplicity is set to **Multiple**. | Compare IBM's import specification UI and chart display directly; confirm how imported records map to multiplicity settings, direction, labels, and user selection in a running IBM installation. Do not collapse records to simplify vector routing. |
| Analysis methods | The transient Analysis Method Card summarizes active-chart entities and isolates, directed/undirected record counts, unordered endpoint pairs and repeats, missing endpoints, and timeline-recognized/blank/unrecognized dates. It states the current groups, bridges, geodesic, and shortest-path assumptions. Its copied text contains aggregate/method metadata only; chart changes and relationship date/direction edits invalidate the cached summary. | Review the card's density and discoverability during native interaction. Compare labels and analysis-method presentation with Analyst's Notebook; current wording describes Arch Notebook algorithms and does not assert IBM parity. |
| Navigation | Persistent workspace destinations, a searchable Quick open palette (Ctrl/Command+K) for analysis workspaces, chart actions and named chart tabs, named SQL searches, saved SQL captures and automation runs, and saved import designs with a remembered source. Quick Open supports multiword search, visible Up/Down selection, Enter activation, and scrolls long result lists to the active choice. It provides a Fit chart command and Ctrl/Command+0 for framing all chart entities, case records, direct routes between sources and automation jobs, plus an analysis-pane width preference retained across app launches. The Most connected ranking and relationship-type filters are stacked for narrow panes; long selected relationship labels are shortened in the control with the full value available on hover. The Sources view follows the active chart and filters SQL and GraphML source metadata by chart ownership. Quick Open's import-design action reinspects the source and opens mapping review without importing chart data. | Validate the navigation flow against common analyst tasks and remove duplicated routes when they do not help the task. |
| Interoperability | CSV/TSV, GraphML, KML, and supported ANX chart import/export, plus portable SQL automation, path, import-design, and Linux CLI analyst finding-packet handoffs. Finding packets include an editable report and SVG overview; the report contains detected community membership, cross-community record/pair/direction totals, and ranked cross-community proxies. Names, chart title, relationship labels, record IDs, and evidence references are independently opt-in; community members and proxies are pseudonymous by default. These are Arch Notebook outputs and do not assert IBM compatibility. Imports stage and validate before applying. In the desktop app, ANX XML parsing runs on a background worker and its result is discarded if the active chart changes before completion; CLI imports remain synchronous. The ANX parser handles UTF-8 and UTF-16 XML, common entity/link shapes and attributes, and Arch Notebook round-trip metadata; unsupported chart-item forms are rejected. Internal acceptance now includes an external-shaped XML case for reverse arrows, named type/strength references, dates, and custom attributes; IBM XSD validation and opening the generated/imported chart in Analyst's Notebook or Chart Reader remain open. Arch Notebook GraphML files preserve chart labels and legends in an Arch-specific graph data property; other GraphML tools may ignore it. The Chart Import menu and `--import-document-packets` CLI accept only bounded `trans-release` handoffs with schema-valid, released, downstream-ready state and a matching approved release reference; they are isolated on a separate chart with no inferred relationships. | Validate ANX import and export against IBM's schema and application, and compare chart round-trip identity/attributes/direction/confidence/metadata against vendor examples. `.anb` is a native binary format and is not currently supported. GraphML and KML do not replace ANX. Agree a versioned Arch Notebook consumer contract with the handoff owner before calling the local importer a supported cross-repository integration; the current upstream handoff targets `trans-downstream`. |
| Ingestion | Read-only SQLite schema inspection and query execution; stable entity/connection identities; immutable, comparable snapshots; typed parameters; entity and connection properties; query-mapped entity representations; selected SQL-backed entities can open saved comparison history filtered by stable source identity and inspect matching current/baseline rows already retained in those snapshots. The entity inspector lists each matching SQL source identity separately and offers per-source saved history and a bounded live read-only query, including for chart items carrying identities from multiple SQL sources. The lookup runs off the UI thread, supports cancellation and timeout, and does not persist source rows. PDF is not an Arch Notebook input format. Eagle-Eye owns source/page/region evidence, `trans` owns transcription, and `trans-release` owns validation and release status. Agree and validate a versioned handoff contract with the owner before treating the local importer as a supported integration. Keep source documents, page images, raw OCR, and unrestricted transcripts in their owning workflow. |

## Reusable SQL Review searches

SQL Review can save database path, series, query text, and typed parameter defaults as a case-local search definition. Loading a definition only restores the current review draft; it does not execute SQL, capture a snapshot, or change an automation job. When saved while chart-seeded review is active, the current selected identity value is omitted and the seed parameter name is retained for rebinding against the current chart selection. This provides reusable named, parameterized searches within the local SQLite workflow. It is inspired by the analyst flow of choosing a named external search, supplying parameters or seeds, reviewing results, and selectively copying records, but IBM External Searches are administrator-configured through i2 Analyze; Arch Notebook's local catalog is not an i2 Analyze connector or server query catalog. See IBM's [External Searches overview](https://docs.i2group.com/anb/10.0.2/i2_connect.html) and [searching external sources](https://docs.i2group.com/anb/9.4.0/search_i2c.html), and the [SQL Review usage guide](sql-ingestion.md#save-and-reuse-a-sql-search). Saved searches also appear in **Quick Open** by name; selecting one opens SQL Review and restores its draft without executing it. See [SQL search catalog acceptance](evidence/sql-automation/SQL-SEARCH-CATALOG-01-20261128.md). Definition packages can move these SQLite drafts between cases through CLI or SQL Review import/export; the imported definition loads for review, and requires later validation before query use and case save to persist. This remains distinct from IBM i2 Analyze server queries. See [SQL-SEARCH-PACKAGE-01](evidence/sql-automation/SQL-SEARCH-PACKAGE-01-current-source-20261128.md) and [SQL-SEARCH-PACKAGE-02](evidence/sql-automation/SQL-SEARCH-PACKAGE-02-desktop-ui-20261128.md).

## SQL seed parameter helper

SQL Review can bind a selected chart entity's SQL external ID to a named one-off parameter, defaulting to `seed_entity_id`. For a multi-entity chart selection, it binds a JSON array of IDs from a shared SQL source to a named parameter (default `seed_entity_ids`), when every selected entity has exactly one identity from that source; SQLite's `json_each` can expose the values to a read-only query. It offers IDs only from SQL snapshots associated with the active chart, and changes only the current review parameter draft. The analyst supplies the SQL predicate, validates it, reviews 200 rows per page, retains selections across pages, and explicitly adds chosen relationships to the chart without creating a snapshot. Up to 16 otherwise-unmapped SQL output columns are shown in bounded transient row detail. Paging follows SQL row order, so an explicit deterministic `ORDER BY` is needed to avoid overlaps or gaps. Saved automation definitions and schedule parameters are not modified. This supports local reviewed selective insertion, but it does not provide the full i2 Analyze external-search integration or server-configured query catalog. See [SQL-SEED-01](evidence/sql-automation/SQL-SEED-01-one-off-parameter-20261128.md) and [SQL-SEED-02](evidence/sql-automation/SQL-SEED-02-multi-entity-json-seed-20261128.md). IBM's **External Searches** workflow is provided when an Analyst's Notebook deployment connects to external sources through i2 Analyze. Administrators configure the available queries; queries may accept values and selected chart items as seeds, and analysts review/filter results before copying chosen records onto a chart. This is a useful interaction reference, but it is not the same feature as the standalone app's local SQLite job scheduler. See IBM's [external search overview](https://docs.i2group.com/anb/10.0.2/i2_connect.html), [searching external sources](https://docs.i2group.com/anb/9.4.0/search_i2c.html), and [results-page workflow](https://docs.i2group.com/anb/10.1.2/working_with_the_results_page.html).

## IBM source-record and import-specification behavior

IBM's Analyst's Notebook documentation distinguishes the source database identity from its captured data record. A chart item can hold a separate data record for each source; the copy represents source values at chart time and is not refreshed just because the upstream source changes. When the connected data source supports editing, an analyst can update it and rechart the item to refresh that record. Arch Notebook keeps the same historical-versus-live distinction through saved SQL snapshots, **Find SQL history**, and a separate bounded **Query live** action, while intentionally keeping SQLite read-only. This parallel is a workflow reference, not a claim of IBM data-record or database-connector compatibility. See IBM's [data records](https://docs.i2group.com/anb/10.1.2/data_records.html) documentation.

IBM import specifications support source inspection, row inclusion/exclusion, value combination/adjustment, entity/link type selection, property mapping, and record matching. Arch Notebook's CSV/TSV import designs implement local mappings, transforms, row filters, preview, last-source reinspection, and stable identity rules, but use an Arch-specific format; IBM `.ximp` and `.oimp` import specifications are not read or written. The recalled path is local case metadata and is omitted from portable import-design packages. Keep this file-level parity separate from ANX chart exchange and validate user workflows in Analyst's Notebook when available. See IBM's [import specification](https://docs.i2group.com/anb/10.1.1/importing_a_file_with_a_new_specification.html) and [format](https://docs.i2group.com/anb/10.1.1/import_specifications.html) documentation.

IBM's current 10.1.2 workflow exposes saved specifications from **Home → Import → Saved Specifications**. A specification can rerun against its last file or be applied to a different file in the same format. The import progress window offers an HTML report; IBM documents that there is no permanent record of the import unless that report is saved. IBM also distinguishes classic `.ximp` from i2 Analyze schema-aligned `.oimp`; they are not interchangeable. Arch Notebook's CSV/TSV import designs and SQL jobs remain separate Arch-specific formats. SQL jobs persist immutable result snapshots, run status, deltas, and bounded history in the case, giving SQL automation an auditable record without implying that Analyst's Notebook accepts Arch's SQL jobs or that SQL is part of IBM's file-import specification workflow. Directly compare the IBM navigation and saved-report flow in a licensed host before changing Arch's import workspace to claim parity. See IBM's [saved-specification workflow](https://docs.i2group.com/anb/10.1.2/import_selected.html), [import overview](https://docs.i2group.com/anb/10.1.2/import_data.html), and [specification formats](https://docs.i2group.com/anb/10.1.2/import_specifications.html).

## Interoperability gate

IBM describes `.anx` as a standardized XML representation of a chart. IBM's [support note on the ANX format](https://www.ibm.com/support/pages/node/546669) identifies the installed Windows directories for examples (`C:\Program Files (x86)\Common Files\i2 Shared\XML\Examples`), documentation (`...\XML\Schema\Documentation\Analyst's Notebook 7.html`), and schema (`...\XML\Schema\Analyst's Notebook 7.xsd`). That note was modified in 2018 and lists Analyst's Notebook versions 8.9 and 9.0; do not assume the named schema is correct for a newer installation. Record the installed product version and schema version with every validation. Until a matching IBM schema and representative chart fixture are available in the development environment, ANX compatibility cannot be claimed or validated. A local search on 2026-11-27 found no `.anx` or `.xsd` files in the repository fixtures/docs, the Linux research share path, or the user's shallow home directories; GraphML/KML support is separate.

IBM's XML import workflow also accepts arbitrary XML when an analyst supplies an XSLT stylesheet, then imports the resulting chart representation. Arch Notebook exposes that adaptation in both the desktop **Import…** menu and `--import-xml-xslt <case.json> <input.xml> <stylesheet.xsl> [--json]`; the desktop operation runs in the background, while the CLI is suitable for scripts. Both require `xsltproc` on `PATH`, transform to ANX, and apply the result through the same strict importer. For example, an organization can maintain a trusted stylesheet that maps its feed's fields into the supported ANX subset. The stylesheet is executable transformation logic and must come from a trusted source. The transform rejects DTD declarations in UTF-8 and UTF-16 source or stylesheet files, disables network fetches and XSLT writes, and caps source and transformed XML at 16 MiB. This internal acceptance demonstrates the configurable pipeline only; it does not validate the resulting ANX against an IBM schema or application. See [XML/XSLT acceptance](evidence/anx/XML-XSLT-IMPORT-01-linux-20261128.md).

The public Rust crate [`anxwritter`](https://docs.rs/anxwritter/latest/anxwritter/) is an export-only option with an MIT license and a Rust 1.88 minimum. Its dependency set includes image, YAML, date/time, regex, and serialization support, so Arch Notebook's first export uses the existing XML stack instead of adding that dependency tree. The crate may still serve as a comparison source for future output validation; it does not provide ANX import or replace IBM fixtures.

When those artifacts are available, copy the schema and vendor examples from the Windows installation into a restricted local test directory, keeping them out of Git unless redistribution is explicitly permitted. Validate both exported and representative imported `.anx` files against the matching schema, check round-trip identity/attributes/direction/confidence/metadata, and open both files in Analyst's Notebook or Chart Reader. Record the application version, schema version, file hashes, validator output, and import result separately; schema validity alone does not prove application acceptance.
