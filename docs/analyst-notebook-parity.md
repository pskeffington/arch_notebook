# Analyst's Notebook compatibility map

Arch Notebook is a Rust desktop application inspired by IBM i2 Analyst's Notebook. This page tracks the product areas that shape its workflow and separates implemented behavior from compatibility gaps.

| Product area | Current Arch Notebook behavior | Remaining compatibility work |
| --- | --- | --- |
| Charting and feel | Dark desktop workspace, typed entities and connections, per-entity Icon, Theme line, Event frame, Box, Circle, or Text block representation, plus standalone chart labels and legends. Labels can be placed, edited, colored, resized, selected, dragged, copied, and deleted without affecting entity analysis. Legends populate from distinct entity types, relationship labels, and item attribute classes; attribute class circle, square, triangle, and diamond symbols can display values on matching entities and relationships. Entries can apply a primary condition plus up to seven additional conditions joined with AND or OR (presence, absence, equality, numeric greater/less thresholds, ISO date comparisons, text containment, and prefix/suffix) to chart-item colors and optional matching-link widths without changing saved data. Chart labels, legend styles, attribute display, and conditional color settings persist per chart and round trip through Arch Notebook GraphML metadata. Representations are persisted and exchanged through CSV/TSV, GraphML, and KML; ANX import/export maps supported chart items and preserves Arch Notebook labels/metadata when available, but has not been checked against IBM's XSD or application. | Expand conditional formatting to nested and mixed AND/OR groups, lookup tables, badges, size, visibility, type, and line styling. Add attribute data types, semantic types, and value formatting. Expand legend coverage to icon frames, fonts, time zones, layout/print positioning, and ANX import/round-trip semantics. Compare the interactive chart and editing flow against Analyst's Notebook in a running visual review; tune theme-line and event-frame behavior, palettes, symbols, canvas gestures, and property editing from direct observation. |
| Relationship multiplicity | Separate relationship records between the same entity pair are retained, drawn on parallel lanes, and individually selectable in Arch Notebook. This matches IBM's documented ability to import multiple links between a pair when chart multiplicity is set to **Multiple**. | Compare IBM's import specification UI and chart display directly; confirm how imported records map to multiplicity settings, direction, labels, and user selection in a running IBM installation. Do not collapse records to simplify vector routing. |
| Navigation | Persistent workspace destinations, a searchable Quick open palette (Ctrl/Command+K) for analysis workspaces and chart actions, named chart tabs, cross-chart search, keyboard navigation, case records, direct routes between captures, sources, and automation jobs, plus an analysis-pane width preference retained across app launches. The Sources view follows the active chart and filters SQL and GraphML source metadata by chart ownership. | Validate the navigation flow against common analyst tasks and remove duplicated routes when they do not help the task. |
| Interoperability | CSV/TSV, GraphML, KML, and supported ANX chart import/export, plus portable SQL automation, path, and import-design packages. Imports stage and validate before applying. In the desktop app, ANX XML parsing runs on a background worker and its result is discarded if the active chart changes before completion; CLI imports remain synchronous. The ANX parser handles UTF-8 and UTF-16 XML, common entity/link shapes and attributes, and Arch Notebook round-trip metadata; unsupported chart-item forms are rejected. IBM XSD validation and opening the generated/imported chart in Analyst's Notebook or Chart Reader remain open. Arch Notebook GraphML files preserve chart labels and legends in an Arch-specific graph data property; other GraphML tools may ignore it. The Chart Import menu and `--import-document-packets` CLI accept only bounded `trans-release` handoffs with schema-valid, released, downstream-ready state and a matching approved release reference; they are isolated on a separate chart with no inferred relationships. | Validate ANX import and export against IBM's schema and application, expand ANX coverage from representative fixtures, and compare chart round-trip identity/attributes/direction/confidence/metadata. `.anb` is a native binary format and is not currently supported. GraphML and KML do not replace ANX. Agree a versioned Arch Notebook consumer contract with the handoff owner before calling the local importer a supported cross-repository integration; the current upstream handoff targets `trans-downstream`. |
| Ingestion | Read-only SQLite schema inspection and query execution; stable entity/connection identities; immutable, comparable snapshots; typed parameters; entity and connection properties; query-mapped entity representations; selected SQL-backed entities can open saved comparison history filtered by stable source identity and inspect matching current/baseline rows already retained in those snapshots. The entity inspector lists each matching SQL source identity separately and offers per-source saved history and a bounded live read-only query, including for chart items carrying identities from multiple SQL sources. The lookup runs off the UI thread, supports cancellation and timeout, and does not persist source rows. PDF is not an Arch Notebook input format. Eagle-Eye owns source/page/region evidence, `trans` owns transcription, and `trans-release` owns validation and release status. The bounded-handoff CLI importer retains workflow IDs, the matching approval reference, release state, bounded evidence-boundary metadata, and allowlisted reporting fields on isolated entities; it rejects unapproved/non-ready states and raw payload markers and creates no relationships. Eagle-Eye implements a bounded local PDF OCR visual backend using pypdfium2 and Tesseract (10 pages by default) that returns bounded observations, while its broader PDF ingestion document remains a specification; this specific 157-page source was processed outside that Eagle-Eye backend. | Validate SQL ingestion on representative production-shaped schemas and queries, with special attention to composite identities, schema evolution, and large result sets. Review query-aware drillback with representative production-shaped IDs and joined queries, including aliases, NULLs, and large result sets. IBM can link chart items to data-source records and, depending on the source, view or update those records; Arch Notebook’s contract intentionally keeps source databases read-only, so database write-back is out of scope. Agree and validate a versioned handoff contract with the owner before treating the local importer as a supported integration. Keep source documents, page images, raw OCR, and unrestricted transcripts in their owning workflow. |
| Adaptability | Case-local chart templates capture entity type representations and colors plus relationship vocabulary. Applying a template styles matching chart entities and supplies defaults for manually added entities; the active template follows chart tabs. Import designs support field mapping, transforms, row filters, and preview. SQL schema inspection provides query templates, drift comparisons, and repair suggestions without rewriting analyst SQL. | Expand templates to include conditional rules and additional chart defaults after workflow review. Templates do not currently alter SQL or file-import mappings. Improve workflow feedback from real analyst use and keep schema-repair suggestions reviewable and non-destructive. |
| SQL automation | Saved jobs run in the app or CLI and can use per-case Linux systemd or macOS LaunchAgent schedules. Query-only preflight, per-run timeouts and cancellation, atomic checkpoints, resumable batches, saved query/parameter provenance, schema fingerprints and object manifests, unchanged-schema policies, regression thresholds, and run-history review support recovery and audit. Preflight can gate on usable connections and schema stability without changing saved jobs. Schedule installation preflights saved parameters and records its policy; **Check schedule** restores that policy. Partial captures with skipped endpoint rows enter the review queue and link back to SQL Review; query-plan inspection and schema-repair suggestions help adapt queries without rewriting analyst SQL. Desktop capture progress reports observed SQL rows, skipped endpoints, relationship application counts, entity counts, and snapshot finalization without persisting transient progress. | Validate scheduler installation, cancellation, restart/resume, and failure recovery through interactive platform review; confirm progress and cancellation behavior during long-running captures. |

**SQL scale acceptance (2026-11-25):** The automated Rust CLI acceptance now exercises a fictional joined email-header schema with composite entity keys, composite message/recipient connection IDs, nullable attributes, repeated endpoint pairs, and 7,121 result rows across two immutable snapshots. All rows were retained and a confidence decline was found in history; the application left the SQLite file unchanged during each read/capture. See the [SQL-SCALE-01 evidence](evidence/sql-automation/SQL-SCALE-01-joined-header-linux-620e733.md). This synthetic fixture does not close validation against real production schemas or the local Clinton email candidate case.

## Local visual review

On 2026-11-24, the Linux/X11 app was opened with an isolated data directory and reviewed at an approximately 1440×900 window size. The workspace showed persistent destinations including Timeline, chart tabs, a left case/search pane, the central chart with its navigator, and the right analysis pane. The review found the chart action row crowded, so CSV/TSV, GraphML, and KML actions were grouped in **Import…** and **Export…** menus. A follow-up runtime review confirmed the updated toolbar also groups layout and viewport actions in **View…**, leaving chart creation and data exchange actions visible. A synthetic local case rendered the new chart legend with entity markers and relationship lines at that size. The right analysis pane remains dense at this window size and should be revisited at common analyst display sizes. Analyst's Notebook was not running in these sessions, so the reviews do not establish visual parity.

On 2026-11-25, isolated Linux/X11 launches at approximately 1440×900 reviewed the analysis-pane layout. A divider supports drag resizing, and plus/minus controls adjust the width in steps. The selected width is now stored in the app's user-data directory and restored on launch, clamped to 240–420 points. The updated persistence behavior and pointer-drag behavior have not been exercised in a live UI session. The broader analysis content is still dense, and no Analyst's Notebook comparison was available.

## Interoperability gate

IBM describes `.anx` as a standardized XML representation of a chart. IBM's support guidance places the XSD and examples in the installed Analyst's Notebook directories. Until an IBM schema and representative chart fixture are available in the development environment, ANX compatibility cannot be claimed or validated. The local availability check found no ANX fixture or schema in the Cargo registry; GraphML/KML support is separate.

The public Rust crate [`anxwritter`](https://docs.rs/anxwritter/latest/anxwritter/) is an export-only option with an MIT license and a Rust 1.88 minimum. Its dependency set includes image, YAML, date/time, regex, and serialization support, so Arch Notebook's first export uses the existing XML stack instead of adding that dependency tree. The crate may still serve as a comparison source for future output validation; it does not provide ANX import or replace IBM fixtures.

When those artifacts are available, the next ANX work should verify import and export against IBM's schema, check round-trip identity/attributes/direction/confidence/metadata, and open both imported and exported files in Analyst's Notebook or Chart Reader. Keep vendor fixtures local and avoid including proprietary artifacts in the repository unless their license explicitly permits redistribution.
