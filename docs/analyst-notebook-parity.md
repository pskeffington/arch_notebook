# Analyst's Notebook compatibility map

Arch Notebook is a Rust desktop application inspired by IBM i2 Analyst's Notebook. This page tracks the product areas that shape its workflow and separates implemented behavior from compatibility gaps.

| Product area | Current Arch Notebook behavior | Remaining compatibility work |
| --- | --- | --- |
| Charting and feel | Dark desktop workspace, typed entities and connections, per-entity Icon, Theme line, Event frame, Box, Circle, or Text block representation, plus standalone chart labels and legends. Labels can be placed, edited, colored, resized, selected, dragged, copied, and deleted without affecting entity analysis. Legends populate from distinct entity types, relationship labels, and item attribute classes; attribute class circle, square, triangle, and diamond symbols can display values on matching entities and relationships. Entries can apply a primary condition plus up to seven additional conditions joined with AND or OR (presence, absence, equality, numeric greater/less thresholds, ISO date comparisons, text containment, and prefix/suffix) to chart-item colors and optional matching-link widths without changing saved data. Chart labels, legend styles, attribute display, and conditional color settings persist per chart and round trip through Arch Notebook GraphML metadata. Representations are persisted and exchanged through CSV/TSV, GraphML, and KML; ANX import/export maps supported chart items and preserves Arch Notebook labels/metadata when available, but has not been checked against IBM's XSD or application. | Expand conditional formatting to nested and mixed AND/OR groups, lookup tables, badges, size, visibility, type, and line styling. Add attribute data types, semantic types, and value formatting. Expand legend coverage to icon frames, fonts, time zones, layout/print positioning, and ANX import/round-trip semantics. Compare the interactive chart and editing flow against Analyst's Notebook in a running visual review; tune theme-line and event-frame behavior, palettes, symbols, canvas gestures, and property editing from direct observation. |
| Relationship multiplicity | Separate relationship records between the same entity pair are retained, drawn on parallel lanes, and individually selectable in Arch Notebook. This matches IBM's documented ability to import multiple links between a pair when chart multiplicity is set to **Multiple**. | Compare IBM's import specification UI and chart display directly; confirm how imported records map to multiplicity settings, direction, labels, and user selection in a running IBM installation. Do not collapse records to simplify vector routing. |
| Analysis methods | The transient Analysis Method Card summarizes active-chart entities and isolates, directed/undirected record counts, unordered endpoint pairs and repeats, missing endpoints, and timeline-recognized/blank/unrecognized dates. It states the current groups, bridges, geodesic, and shortest-path assumptions. Its copied text contains aggregate/method metadata only; chart changes and relationship date/direction edits invalidate the cached summary. | Review the card's density and discoverability during native interaction. Compare labels and analysis-method presentation with Analyst's Notebook; current wording describes Arch Notebook algorithms and does not assert IBM parity. |
| Navigation | Persistent workspace destinations, a searchable Quick open palette (Ctrl/Command+K) for analysis workspaces and chart actions, named chart tabs, cross-chart search, keyboard navigation, a Fit chart command in Quick open and Ctrl/Command+0 for framing all chart entities, case records, direct routes between captures, sources, and automation jobs, plus an analysis-pane width preference retained across app launches. The Most connected ranking and relationship-type filters are stacked for narrow panes; long selected relationship labels are shortened in the control with the full value available on hover. The Sources view follows the active chart and filters SQL and GraphML source metadata by chart ownership. | Validate the navigation flow against common analyst tasks and remove duplicated routes when they do not help the task. |
| Interoperability | CSV/TSV, GraphML, KML, and supported ANX chart import/export, plus portable SQL automation, path, import-design, and Linux CLI analyst finding-packet handoffs. Finding packets include an editable report and SVG overview; the report contains detected community membership, cross-community record/pair/direction totals, and ranked cross-community proxies. Names, chart title, relationship labels, record IDs, and evidence references are independently opt-in; community members and proxies are pseudonymous by default. These are Arch Notebook outputs and do not assert IBM compatibility. Imports stage and validate before applying. In the desktop app, ANX XML parsing runs on a background worker and its result is discarded if the active chart changes before completion; CLI imports remain synchronous. The ANX parser handles UTF-8 and UTF-16 XML, common entity/link shapes and attributes, and Arch Notebook round-trip metadata; unsupported chart-item forms are rejected. IBM XSD validation and opening the generated/imported chart in Analyst's Notebook or Chart Reader remain open. Arch Notebook GraphML files preserve chart labels and legends in an Arch-specific graph data property; other GraphML tools may ignore it. The Chart Import menu and `--import-document-packets` CLI accept only bounded `trans-release` handoffs with schema-valid, released, downstream-ready state and a matching approved release reference; they are isolated on a separate chart with no inferred relationships. | Validate ANX import and export against IBM's schema and application, expand ANX coverage from representative fixtures, and compare chart round-trip identity/attributes/direction/confidence/metadata. `.anb` is a native binary format and is not currently supported. GraphML and KML do not replace ANX. Agree a versioned Arch Notebook consumer contract with the handoff owner before calling the local importer a supported cross-repository integration; the current upstream handoff targets `trans-downstream`. |
| Ingestion | Read-only SQLite schema inspection and query execution; stable entity/connection identities; immutable, comparable snapshots; typed parameters; entity and connection properties; query-mapped entity representations; selected SQL-backed entities can open saved comparison history filtered by stable source identity and inspect matching current/baseline rows already retained in those snapshots. The entity inspector lists each matching SQL source identity separately and offers per-source saved history and a bounded live read-only query, including for chart items carrying identities from multiple SQL sources. The lookup runs off the UI thread, supports cancellation and timeout, and does not persist source rows. PDF is not an Arch Notebook input format. Eagle-Eye owns source/page/region evidence, `trans` owns transcription, and `trans-release` owns validation and release status. The bounded-handoff CLI importer retains workflow IDs, the matching approval reference, release state, bounded evidence-boundary metadata, and allowlisted reporting fields on isolated entities; it rejects unapproved/non-ready states and raw payload markers and creates no relationships. Eagle-Eye implements a bounded local PDF OCR visual backend using pypdfium2 and Tesseract (10 pages by default) that returns bounded observations, while its broader PDF ingestion document remains a specification; this specific 157-page source was processed outside that Eagle-Eye backend. | Validate SQL ingestion on representative production-shaped schemas and queries, with special attention to composite identities, schema evolution, and large result sets. Review query-aware drillback with representative production-shaped IDs and joined queries, including aliases, NULLs, and large result sets. IBM can link chart items to data-source records and, depending on the source, view or update those records; Arch Notebook’s contract intentionally keeps source databases read-only, so database write-back is out of scope. Agree and validate a versioned handoff contract with the owner before treating the local importer as a supported integration. Keep source documents, page images, raw OCR, and unrestricted transcripts in their owning workflow. |
| Adaptability | Case-local chart templates capture entity type representations and colors, relationship vocabulary, and up to 96 conditional attribute-formatting rules. Applying a template styles matching chart entities, supplies defaults for manually added entities, and adds visible template-owned legends whose rules take precedence over conflicting local legend rules. Reapplication replaces generated rule legends; deletion removes them. Import designs support field mapping, transforms, row filters, and preview. SQL schema inspection provides query templates, drift comparisons, and repair suggestions without rewriting analyst SQL. | Review template application and conditional-style precedence during native interaction. Templates do not alter SQL or file-import mappings. Improve workflow feedback from real analyst use and keep schema-repair suggestions reviewable and non-destructive. |
| SQL automation | Saved jobs run in the app or CLI and can use per-case Linux systemd or macOS LaunchAgent schedules. Query-only preflight, per-run timeouts and cancellation, atomic checkpoints, resumable batches, saved query/parameter provenance, schema fingerprints and object manifests, unchanged-schema policies, regression thresholds, and run-history review support recovery and audit. Preflight can gate on usable connections and schema stability without changing saved jobs. Schedule installation preflights saved parameters and records its policy; **Check schedule** restores that policy. Partial captures with skipped endpoint rows enter the review queue and link back to SQL Review; query-plan inspection and schema-repair suggestions help adapt queries without rewriting analyst SQL. Desktop capture progress reports observed SQL rows, skipped endpoints, relationship application counts, entity counts, and snapshot finalization without persisting transient progress. A headless event regression clicks Cancel automation during a long query and confirms cancellation plus prior checkpoint retention. Current installed-release harnesses pass SQL capture/recovery and generated Linux/macOS scheduler runners using isolated `systemctl`/`launchctl` stubs; see [SQL-AUTO-07](evidence/sql-automation/SQL-AUTO-07-current-installed-release-linux.md) and [SQL-SCHED-07](evidence/sql-automation/SQL-SCHED-07-current-installed-release-linux.md). | Validate live scheduler installation and dispatch, restart/resume, and failure recovery through interactive platform review; confirm progress and cancellation behavior during long-running captures. |

## IBM source-record and import-specification behavior

IBM's Analyst's Notebook documentation distinguishes the source database identity from its captured data record. A chart item can hold a separate data record for each source; the copy represents source values at chart time and is not refreshed just because the upstream source changes. When the connected data source supports editing, an analyst can update it and rechart the item to refresh that record. Arch Notebook keeps the same historical-versus-live distinction through saved SQL snapshots, **Find SQL history**, and a separate bounded **Query live** action, while intentionally keeping SQLite read-only. This parallel is a workflow reference, not a claim of IBM data-record or database-connector compatibility. See IBM's [data records](https://docs.i2group.com/anb/10.1.2/data_records.html) documentation.

IBM import specifications support source inspection, row inclusion/exclusion, value combination/adjustment, entity/link type selection, property mapping, and record matching. Arch Notebook's CSV/TSV import designs implement local mappings, transforms, row filters, preview, and stable identity rules, but use an Arch-specific format; IBM `.ximp` and `.oimp` import specifications are not read or written. Keep this file-level parity separate from ANX chart exchange and validate user workflows in Analyst's Notebook when available. See IBM's [import specification](https://docs.i2group.com/anb/10.1.1/importing_a_file_with_a_new_specification.html) and [format](https://docs.i2group.com/anb/10.1.1/import_specifications.html) documentation.

## Interoperability gate

IBM describes `.anx` as a standardized XML representation of a chart. IBM's support guidance places the XSD and examples in the installed Analyst's Notebook directories. Until an IBM schema and representative chart fixture are available in the development environment, ANX compatibility cannot be claimed or validated. The local availability check found no ANX fixture or schema in the Cargo registry; GraphML/KML support is separate.

The public Rust crate [`anxwritter`](https://docs.rs/anxwritter/latest/anxwritter/) is an export-only option with an MIT license and a Rust 1.88 minimum. Its dependency set includes image, YAML, date/time, regex, and serialization support, so Arch Notebook's first export uses the existing XML stack instead of adding that dependency tree. The crate may still serve as a comparison source for future output validation; it does not provide ANX import or replace IBM fixtures.

When those artifacts are available, the next ANX work should verify import and export against IBM's schema, check round-trip identity/attributes/direction/confidence/metadata, and open both imported and exported files in Analyst's Notebook or Chart Reader. Keep vendor fixtures local and avoid including proprietary artifacts in the repository unless their license explicitly permits redistribution.
