# Political email and records cases for ingestion QA

**Task / owner:** Arch Notebook public-record QA source research / Codex single-session
**Research date:** 2026-11-28
**Purpose:** identify a balanced, reproducible starter set for testing PDF/email extraction, provenance, redaction handling, entity resolution, relationship multiplicity, timelines, and queryable SQL exports.
**Status:** source manifest only; records have not been downloaded, normalized, or imported into a case. Each entry distinguishes primary documents from secondary reporting and allegations from findings.

## Selection and handling

The list favors public records or agency documents from 2025–2026 and includes a mix of official releases, oversight material, and court/FOIA matters. A case is not a finding of wrongdoing. Congressional press releases state the issuer's characterization; where possible, follow the linked record, report, docket, or full production and preserve the agency's response. Several sources are partial/interim and redacted. Avoid adding hacked or unlawfully obtained email dumps. Before importing, confirm the linked source is an official/public release, check privacy/redaction status, download into a dedicated QA corpus directory, hash the originals, and retain source URLs plus retrieval timestamps.

## QA ingestion gates

- Record exact source URL, title, publisher, release date, retrieval time, hash, media type, and whether it is an original record, official index, court filing, or secondary report.
- Keep allegations, official findings, denials, and analyst notes in separate fields; never convert a press-release characterization into a fact label.
- Preserve redaction markers, page numbers, quoted/forwarded message boundaries, attachments, message dates/time zones, and duplicate/thread relationships.
- Deduplicate using stable source IDs where available, then message-id/hash; retain the source record and explain any merge.
- Import in an isolated test case. Validate entity/relationship counts, SQL read-only snapshot behavior, repeat-run deltas, and source-file hash stability before promoting a case into routine QA.
- Prefer non-sensitive official releases. Exclude sealed/classified material, personal contact details that should remain redacted, hacked dumps, and unrelated sensitive personal records.
